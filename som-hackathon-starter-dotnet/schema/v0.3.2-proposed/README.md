## Decided in this pack

None of these holds the IBC pack, and each is seeded rather than left open — the pattern throughout is seed the floor, let the registry govern extension.

- **`ORPHAN`** — ships in v0.3.2 as specified (Option-B; shell ALWAYS retires to ARCHIVED, Morag accepted 13 Jul). Residual debate — reject semantics, two-shells-one-story — tracks to the v0.4 review.
- **DETECTION `claim` shape** — **seeded, not deferred.** The assertion envelope already carries the subject (`target`), the method (`provenance`), the score (`confidence`) and the editorial act (`review`), so the claim itself needs only two fields: `detection_class` (what was looked for) and `verdict` (the finding). Both are now required for DETECTION; per-detector fields extend underneath, governed by the registry. Proven against the two detection cases the demo actually runs — synthetic-media detection on the UGC clip, and C2PA validation carrying an authenticity verdict rather than a manipulation score. Both fit without a single per-detector field in the seed.
- **`transforms[].params` per-type shapes** — **decided.** Per-type payloads as documented (CROP / TRIM / CAPTION_BURN); extension governed by the transform-type registry; consumers ignore unknown keys.
- **`time_range` on a non-TAMS `locator`** — **pinned, not deferred.** Ranges against a `locator` are offset from the referenced file's own zero. A SOM locator points at a stored file, not a conform against embedded source timecode, so the classic ten-hour-start and source-versus-record reconciliation problem never arises. Where a non-TAMS store carries its own internal timing the range is still offset from the file's zero, never from an embedded label — which keeps the door open for stores that segment natively rather than constraining them.

## Still open

- **"Live ingest source" as a first-class story field** — no shape drafted before the pack, so it slips to v0.4 (per its own rule). Continues to ride `extensions.com.{vendor}.livestream_url` (proposed out of Trint's integration, 15 Jul; a public livestream URL to transcribe is a live ingest input, not store-managed media, so it is neither a `media_refs[]` entry nor an arrival event).
- **`assertion.target` vs the audit target set** — `assertion.target.kind` carries STORY; the locked audit `target.kind` does not. Proposed: add STORY to the audit target set so the two converge and the "reuses the audit target set" claim becomes literally true again. Until then the assertion set is deliberately the wider of the two and its description says so. **Governance note:** the audit action/target sets are described as locked, so any addition is a WG call, not a pack edit.
- **Recording an ORPHAN adoption** — the ORPHAN lifecycle commits to an audit record of the move, and the locked action vocabulary (CLEARED / SUPPRESSED / WITHHELD / OVERRIDDEN) cannot express an association. Proposed: an `ASSOCIATED` action. Same governance note as above — this makes good on a commitment the schema already prints rather than adding new behaviour.
- **`blocks[]` consistency** — `editorial_gate.blocks[]` carries the structured `{kind, ref}` shape with bare strings deprecated for migration; `skill.warning.raised.blocks` is still a bare `array of string` with no description. Aligning it means adding a fourth changed family to this pack, so it is flagged here rather than done.
